# Первое упражнение: Codex + GitHub

Вы описываете результат обычными словами. Codex меняет файлы и проверяет работу. Git сохраняет историю изменений на Mac, а GitHub хранит отправленную копию и помогает обсуждать изменения.

Репозиторий проекта: [Costapop/x2](https://github.com/Costapop/x2).

## 1. Посмотрите, что уже есть

Откройте `index.html` на Mac. В версии 2.0.0 выберите режим **«Квадратное · x²»**. Введите `a = 1`, `b = −3`, `c = −4`. Должны появиться корни `−1` и `4`; парабола пересечёт горизонтальную ось в этих точках.

В Codex можно написать:

> Объясни устройство этого приложения простыми словами. Покажи, где вычисляются корни и где рисуется график. Пока ничего не меняй.

## 2. Попросите одно небольшое изменение

Например:

> В репозитории Costapop/x2 создай ветку codex/downward-example. Добавь кнопку примера «Ветви вниз» с коэффициентами −1, 2, 3. Проверь, что корни равны −1 и 3, а вершина находится в точке (1; 4). Покажи результат и изменения файлов.

**Ветка** — отдельная линия работы. Основная версия обычно называется `main`; эксперимент можно проверить до его включения в неё.

## 3. Проверьте результат

Откройте приложение и нажмите новую кнопку. Посмотрите изменения файлов в Codex. **Diff** показывает удалённые и добавленные строки.

Попросите:

> Запусти математические тесты. Объясни, что именно они проверяют, и проверь новый пример в браузере.

Тесты проверяют ответы на известных уравнениях, а просмотр в браузере — вид и работу интерфейса. Одно не заменяет другое.

## 4. Сохраните и отправьте изменение

Когда результат устраивает:

> Создай коммит с понятным сообщением, отправь ветку в Costapop/x2 и открой pull request в main. В описании коротко укажи, что изменилось и что проверено. Не объединяй pull request.

**Коммит** — сохранённый снимок изменений. **Push** — отправка коммитов на GitHub. **Pull request (PR)** — предложение добавить изменения ветки в основную версию.

Для отправки необходим вход в GitHub с правами записи в этот репозиторий. Подключение GitHub в Codex и авторизация Git для командной строки могут требовать отдельной настройки. Если Codex сообщает об отсутствии доступа, подключите GitHub доступным способом в приложении; не вставляйте токены или пароли в чат.

## 5. Посмотрите автоматические проверки

В pull request откройте **Checks** или перейдите на вкладку **Actions** репозитория. Файл `.github/workflows/tests.yml` запускает тесты после отправки изменений и при создании PR, если GitHub Actions разрешён в репозитории.

Зелёная проверка означает, что заложенные тесты прошли. Она не гарантирует отсутствие любых ошибок.

После просмотра diff и работающего приложения можно дать Codex отдельную команду объединить конкретный PR. **Merge** включает проверенное изменение в `main`. Затем обновите локальную `main`, чтобы на Mac была та же версия.

## Необязательно: проверка PR самим Codex

Чтобы запрашивать проверку прямо на GitHub, сначала подключите репозиторий к Codex cloud и включите **Code review** для него в настройках Codex. После этого комментарий `@codex review` в PR запускает проверку. Обычного наличия файлов на GitHub для этого недостаточно. Источник: [официальное руководство OpenAI](https://learn.chatgpt.com/docs/third-party/github).

## Шпаргалка

| Понятие | На примере приложения |
| --- | --- |
| Репозиторий | Все файлы приложения и их история |
| Ветка | Место для работы над кнопкой «Ветви вниз» |
| Diff | Строки, добавленные для новой кнопки |
| Коммит | Сохранённое изменение с описанием |
| Push | Передача изменения с Mac на GitHub |
| PR | Предложение включить кнопку в основную версию |
| Checks | Проверка, что математика продолжает работать |
| Merge | Включение изменения в `main` |

Рабочий цикл: **задача → ветка → изменение → проверка → коммит → push → PR → просмотр → merge**.
